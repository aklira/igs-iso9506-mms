# T3 — `igsmms-client`, the command line client

## Prompt

Run task T3 of `IMPLEMENTATION.md`: a command line (clap) to connect, browse names, read, write and
print the decoded PDUs. Done when `--help` is documented, and a run against the bench peer is recorded
here.

## Summary

- **Code**: `crates/igs-iso9506-mms/src/bin/igsmms-client.rs`, and the client API extended by
  `Client::abort`, the `Trace` event, `in_scope_capabilities` and the lenient option.
- **Commands**: `identify`, `names [--class] [--domain]`, `read NAME [--domain]`,
  `write NAME VALUE [--domain] [--kind]`, `attributes NAME [--domain]`. Global options: `--server`,
  `--trace`, `--timeout`, `--nesting`, `--lenient-parameter-cbbs`.
- **Interoperability found while running it** (`docs/capabilities.md`): G7 (the peer sets a service
  that was not proposed, now ignored as the standard says), G8 (the peer negotiates no parameter CBB
  but serves the services that need them), G9 (identifiers of up to 39 characters), G10 (data nested
  deeper than negotiated; the CLI proposes 6), G11 (a data tag of a later edition, kept raw).
- **Decisions**: D-022.
- **Gate**: `porte=1`.

## Reference run against the bench peer

The reference server is `server_example_basic_io` (libiec61850 v1.6.2.1), published on
`127.0.0.1:10102` by the bench. Commands run from the repository, with `--timeout 10`. The outputs are
the ones the binary printed; the exit status is the shell's.

```
$ igsmms-client -s 127.0.0.1:10102 --timeout 10 identify
vendor: MZ
model: basic io
revision: 1.6.0
[exit 0]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 names --class domain
simpleIOGenericIO
[exit 0]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 names --domain simpleIOGenericIO
igsmms-client: a protocol layer refused an event: the PDU is not allowed by the negotiation
hint: the negotiated CBBs do not allow this request; a server that answers it anyway can be used with --lenient-parameter-cbbs (docs/capabilities.md, G8)
[exit 1]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 --lenient-parameter-cbbs names --domain simpleIOGenericIO --class named-variable
igsmms-client: the connection ended before the answer
[exit 1]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 --lenient-parameter-cbbs read LLN0 --domain simpleIOGenericIO
{{1, BitString(BitString { unused: 3, bytes: [0, 0] }), Unsupported { tag: 17, raw: RawBer([145, 8, 0, 0, 0, 0, 0, 0, 0, 0]) }}, ...
[exit 0]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 --lenient-parameter-cbbs attributes LLN0 --domain simpleIOGenericIO
deletable: false
address: None
type: Structure(TypeDescriptionStructure { packed: None, components: [...] })
[exit 0]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 --lenient-parameter-cbbs read anything
failure: DataAccessError(10)
[exit 0]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 --lenient-parameter-cbbs write anything 42
failure: DataAccessError(9)
[exit 0]

$ igsmms-client -s 127.0.0.1:10102 --timeout 10 identify --server 127.0.0.1:1
igsmms-client: the connection was not established in time
[exit 1]
```

Reading the transcript: `identify` and the domain listing work with the conformant default. The
variable services need the lenient option, because the peer negotiates no parameter CBB (G8). With
it, the peer answers: `DataAccessError(10)` is object-non-existent, `DataAccessError(9)` an access
failure. The listing of the variables of the domain ends the connection: the peer returns identifiers
longer than 32 characters (G9).

## Recorded, not fixed

G1 (the release is not confirmed: the client aborts), G8 (default conformant, option available), G9 (IEC
61850 names, the IEC 61850 phase), G10 (the CLI proposes 6), G11 (kept raw).
