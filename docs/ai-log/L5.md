# L5 — Requests

## Prompt

Run task L5 of `IMPLEMENTATION.md`: invoke IDs, the outstanding limit, the matching of responses, the
timeouts, Cancel, Reject and the unconfirmed PDUs, with fake-clock tests, including a response with
an unknown invoke ID.

## Summary

- **Code**: `crates/igs-iso9506-mms-link/src/requests.rs`. `Requests` owns the association of task L4
  and takes the time in `handle(event, now)`.
  - Requester: `Request` (invoke ID, limit), `Cancel`, and the responses, errors and cancel answers
    received, matched by invoke ID and service.
  - Responder: indications, `Respond`, and `CancelAnswer` (accepted: cancel response then the error
    of the request; refused: Cancel-ErrorPDU).
  - Reject PDUs for an unknown response, an unknown cancel, a duplicate or excess request, and an
    unsupported request or unconfirmed service.
  - Timeouts: reported once per request; the request stays outstanding.
- **Decisions**: D-019.
- **Tests**: `tests/requests.rs`, 17 tests on both roles on a fake clock.
- **Gate**: `porte=1`. `cargo deny` reports the same unused ISC allowance as before.
- **Known gaps**: the Reject of a PDU of the responder's own responses is only recorded, not acted
  upon; the cancel of an incoming request that the user does not answer is not timed out.
