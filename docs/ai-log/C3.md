# C3 — Session SPDUs

## Prompt

Run task C3 of `IMPLEMENTATION.md`.

## Summary

Added `igs_iso9506_mms_codec::session`. It decodes and encodes, field by field, the SPDUs that the
profile needs (IEC 60870-6-702 table A.61: version 2, duplex, kernel):

- CONNECT, ACCEPT and REFUSE, with their parameter groups;
- FINISH and DISCONNECT;
- ABORT and ABORT ACCEPT;
- GIVE TOKENS and DATA TRANSFER, in the basic concatenation that carries data.

It also has `decode_tsdu` and `encode_tsdu` for the concatenation rules of §6.3.7, and a typed
`Error`. Other SPDUs and unknown parameters are kept as received (D-009).

**Tests**: `tests/session.rs` has 13 tests:

- the CONNECT, ACCEPT and GIVE TOKENS with DATA TRANSFER observed on the bench, decoded and
  re-encoded octet for octet;
- a hand-written vector for each SPDU;
- the three-octet length indicator, and the Extended User Data parameter beyond 512 octets;
- the concatenation rules, and the mandatory parameters;
- malformed fields.

**Found by a throwaway noise run**: units received out of order decoded to a value that changed
after one encode and decode. Units are now sorted by code on decode. A regression test pins it,
and a second run of 2 million inputs was stable, with no panic.

Two lengths in the tests were miscomputed by hand; the encoder was right.
