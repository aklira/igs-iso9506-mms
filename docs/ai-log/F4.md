# F4 — Code generation

## Prompt

Run task F4 of `IMPLEMENTATION.md`.

## Summary

`cargo xtask codegen` now reads the modules and the data files of tasks P3 and P4 and writes
`crates/igs-iso9506-mms-codec/src/generated/`. `--check` fails when the committed files are stale.

- `xtask/src/asn.rs`: a reader for the subset of ASN.1 that the modules use. It reads the extension
  markers, including the end marker that stopped `rasn-compiler`. Comments are dropped by the
  tokenizer, so none reaches the output.
- `xtask/src/emit.rs`: the types reachable from the MMS PDU and the ACSE APDU, 143 in all, and the
  tables.
- `crates/igs-iso9506-mms-codec/src/schema.rs`: the hand-written vocabulary of the generated code.
- `crates/igs-iso9506-mms-codec/tests/generated.rs`: 12 tests on counts, scope, tags and
  constraints. They need no `docs/spec/`.

**Not in this task**: generated code has no decoding or encoding yet. It needs the BER layer of
task C1; the codec tasks add it to this generator. Scope and integer choices are D-004 and D-005.

Every type assignment of the five modules parses, except information object classes and objects,
which the reader skips. Implicit tags on a CHOICE become explicit by reference to the target
type; three tests pin this and the module default.

`serde` and `serde-saphyr` are new, in `xtask` only. `serde_yaml`, used by `igs-iec104`, was left
out because its advisory would have needed an exception in `deny.toml`. `serde-saphyr` needs
Rust 1.89: the versions that declare less do not build on 1.85 either. So `xtask` has its own
`rust-version` and the minimum-version job of the workflow excludes it (D-006). The workspace
moved to resolver 3, so that the library crates stay within their minimum version.
