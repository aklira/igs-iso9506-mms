# F3 — Codec approach

## Prompt

Run task F3 of `IMPLEMENTATION.md`.

## Summary

Compared `rasn` 0.30 with `rasn-compiler` 0.16 against a small BER reader and generator of this
project, on `Data`, `ConfirmedServiceRequest` and `AARQ-apdu`. **Choice: the project's own codec**,
recorded as D-003 in `PROVENANCE.md`.

The trial code stayed outside this repository, because its generated output mirrors the licensed
modules. Nothing from it is committed.

| Test | `rasn` + `rasn-compiler` | Prototype |
| --- | --- | --- |
| Generation of `Data` | Compiles | Compiles |
| `ConfirmedServiceRequest` | Refused; accepted once one end marker is removed | 85 services and `additionalService` |
| `AARQ-apdu` | Refused; accepted after rewriting the markers | 16 fields |
| Whole MMS and ACSE set | 63 compile errors after three input rewrites, 15 in the main MMS module | Not tried |
| Valid frame, long-form length | Accepted | Accepted, encoding identical to the input |
| Nesting of 500 to 100,000 levels, definite and indefinite, 2 MiB stack | Error | Error |
| Oversized lengths | Error | Error |
| 3 million noisy inputs | No panic | No panic |
| Unknown tag | Error | Unsupported variant, raw bytes kept |
| Lints of rule 8 on the decoding path | Outside our control | Active, none raised |
| `unsafe` | 2 blocks in `rasn` | None |
| Added crates | 35 | 0 |

`rasn` did better than expected at run time: criterion 1 does not separate the two. The generator
decides it. A size constraint with two allowed values also came out as a range, which accepts the
values in between.

The prototype is about 120 lines of runtime and 70 of generator. It does not show that the full
generator of task F4 is easy: it leaves service and ACSE field contents raw, and it has not met
nested CHOICE tagging, which F4 and the codec tasks must handle.
