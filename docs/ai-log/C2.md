# C2 — TPKT and COTP TPDUs

## Prompt

Run task C2 of `IMPLEMENTATION.md`.

## Summary

Added `igs_iso9506_mms_codec::transport`, with:

- TPKT framing (RFC 1006): `encode_frame`, and `FrameDecoder`, which cuts a byte stream into TPDUs
  whatever the size of the pieces and refuses a wrong version or length.
- The class 0 TPDUs of X.224 §13: CR, CC, DR, DT and ER, decoded and encoded by `Tpdu`.
- A typed `Error` that gives the reject cause and the offset of the octet in fault, so that the
  connection can build an ER TPDU.

What the decoder accepts, and what is left to the connection, is D-008.

**Tests**: `tests/transport.rs` has 14 tests:

- the CR and CC TPDUs observed on the bench, decoded and re-encoded octet for octet;
- vectors for each TPDU;
- the parameter rules of §13.2.3: undefined parameters ignored in a CR only, last value of a
  duplicate wins;
- the header length rules, and the TPDU types outside class 0;
- a stream of five TPKTs, cut at every octet boundary, fed one octet at a time and all at once.

**Observed on the bench**: the reference peer negotiates a TPDU size of 8192 octets, which X.224
does not allow in class 0. Task L2 must decide whether to accept it.

Three hand-written vectors had a wrong length indicator. The decoder refused each of them for the
right reason, and the vectors were fixed. A throwaway noise run of 1 million inputs in a debug build
found no panic.
