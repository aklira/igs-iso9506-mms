# F5 — Interop bench skeleton

## Prompt

Run task F5 of `IMPLEMENTATION.md`.

## Summary

Added `bench/`, after the bench of `igs-iec104`: `pyproject.toml`, `docker-compose.yml`, the compose,
capture and `tshark` helpers, and one scenario.

**Reference peer**: the example programs of libiec61850, tag `v1.6.2.1`, commit `c28c27c`, built by
`bench/peer/Dockerfile`. The source stays in the build stage. It was not read: the agent only listed
the names of the built programs, and read the usage printed by `mms_utility`.

**Scenario**: `mms_utility` asks `server_example_basic_io` for its identity and its domains. The
capture shows the COTP connection, Initiate, then two confirmed requests with their responses.
`tshark` recognises TPKT, COTP, session, presentation, ACSE and MMS and reports no malformed frame
and no error-level expert info. No code of this project takes part yet.

**Observed, for later tasks**: this client ended by closing TCP, with no Conclude in the capture.

**Two capture races, found by the scenario and fixed**: `tcpdump` could start after the short
exchange, so `capture.wait_live` now waits until the file records traffic. And `tcpdump` lost the
last frames when stopped, because the kernel had not delivered them yet, so it runs with
`--immediate-mode`. The `igs-iec104` bench has no such flag: its exchanges last longer.

The host has Podman, not Docker. The bench was run with `podman-compose`. The scenario passed five
runs in a row.
