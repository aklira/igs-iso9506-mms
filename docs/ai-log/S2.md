# S2 — Server

## Prompt

Run task S2 of `IMPLEMENTATION.md`: a multi-client `Server`: Initiate, the services in scope, unsolicited
reports, the CBB check on every PDU, Reject and error responses. Done when the integration tests per service
pass with the `Client`.

## Summary

- **Code**: `crates/igs-iso9506-mms/src/server/` (`mod.rs`: the listener, the associations, the model task;
  `service.rs`: the services on the model). Public as `igs_iso9506_mms::{Server, ServerConfig}` and
  `igs_iso9506_mms::server`.
- **Design**: one task owns the model; each association sends its indicated requests to it and waits for
  the answer. The association is the responder side of the link layer, so the CBB check, the Reject PDU and
  the release are the link's.
- **Capabilities**: the in-scope services; the parameter CBBs `str1`, `str2`, `vnam`, `vlis`.
- **Decisions**: D-026.
- **Tests**: 15 integration tests in `tests/server.rs`, with the client of this repository over TCP on the
  loopback; the first run found one fault in the test (a list name with a hyphen, which the codec does not
  accept as an identifier), not in the server.
- **Gaps**: recorded in `docs/capabilities.md` (the reports go to every association; one task serves all;
  no access control; addresses refused; the Reject of an unserved request is covered by the codec tests only).
- **Gate**: `porte=1` (fmt, clippy, doc, test, msrv 1.85, deny, codegen --check).

## Reading

ISO 9506-2 §7 (services), §8 (the CBBs of each PDU), §6 (Reject), §14.6 to §14.14 (variable access and
lists). No standard text is in the code or the docs: the clauses are cited, and the rules are in the
project's own words.
