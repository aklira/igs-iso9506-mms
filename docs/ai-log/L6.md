# L6 — Interoperability of the stack

## Prompt

Run task L6 of `IMPLEMENTATION.md`: bench scenarios for the association, the Initiate, the Conclude
and the Abort, in both directions as the peer allows. Done when they pass, or the gap is recorded.

## Summary

- **Scenarios**: `crates/igs-iso9506-mms/tests/interop.rs` (ignored unless `MMS_PEER` is set), and
  `bench/tests/test_l6_interop.py`, which starts the reference server with its capture and checks the
  capture in tshark.
  - Association and Initiate: the peer negotiates version 1, outstanding 5, nesting 2.
  - Identify, confirmed: answered with the vendor name.
  - Abort by the user: accepted; the peer closes the stream.
  - Conclude: the peer answers the CONCLUDE request; it does not answer the ACSE release (gap G1).
- **Defects found and fixed by the interop**:
  - The initiator sent the ACSE release together with the CONCLUDE request. Annex A.1.2.1 sends it
    after the CONCLUDE response. The peer ignored it. Fixed in the association (`16b47a9` is the CPA;
    this fix is in the L6 commit).
  - The responder waited for the release before answering the CONCLUDE request. It now answers at
    once (Annex A.1.2.2).
  - The user abort carried an empty ARU PPDU. It now carries no user data (X.225 §8.3.9.6); the
    empty PPDU was read as an MMS PDU of zero bytes by tshark.
- **Recorded**: `docs/capabilities.md` (gaps G1 to G6), D-017 and D-018 updated.
- **Gate**: `porte=1` at the commit.
- **Not done**: the reference client as initiator against this stack (phase S); the services beyond
  Identify.
